## How It Works

### Workflow

1. **User selects Hand Sign Recognition job** → Creates job with operation='hand_sign_recognition'
2. **User uploads Kaggle dataset ZIP** → Chunked upload (reuses existing mechanism)
3. **Host receives and validates ZIP** → Extracts and inspects directory structure
4. **Host identifies classes** → Reads class directories and labels from dataset
5. **Host trains MobileNetV2 model** → 10 epochs with GPU acceleration (CUDA/MPS)
6. **Host generates model + metadata** → PyTorch weights + JSON with class mapping
7. **Host sends model back to User** → Via existing file download endpoint
8. **User stores trained model locally** → Ready for inference

### Key Design Decisions

#### 1. Reuse Existing Infrastructure
- **File transfers**: Used existing chunked upload/download with progress tracking
- **Job lifecycle**: Same status/stage system as other jobs
- **Authentication**: Same token-based auth as Object Detection/Image Similarity
- **WebSocket**: Same real-time updates mechanism

#### 2. Dataset Structure Detection
The `extract_and_validate_dataset()` function intelligently handles:
- Direct ZIP structure: `dataset.zip` → `ClassA/`, `ClassB/`, `ClassC/` (with images)
- Nested ZIP structure: `dataset.zip` → `hand_signs/` → `A/`, `B/`, `C/` (with images)

This avoids hardcoding assumptions about ZIP layout.

#### 3. No Hardcoded Classes
The model doesn't assume specific hand signs (A-Z, etc.). It:
- Reads class names from directory names
- Creates class-to-index mappings dynamically
- Returns these mappings in metadata JSON for inference

#### 4. Metadata Design
Generated `hand_sign_metadata.json` includes:
```json
{
  "model_name": "Hand Sign Recognition Model",
  "model_architecture": "MobileNetV2",
  "num_classes": 3,
  "classes": {"0": "A", "1": "B", "2": "C"},
  "class_to_index": {"A": 0, "B": 1, "C": 2},
  "input_size": 224,
  "preprocessing": {...},
  "training": {...},
  "metrics": {...},
  "inference": {...}
}
```

This enables users to perform inference without hardcoding anything.

#### 5. GPU Support
- Automatically detects CUDA, MPS (Apple Silicon), or CPU via existing `get_hardware_info()`
- Uses the same device for training
- Logs device used in metadata for reproducibility

## Example: Using the Trained Model

```python
import torch
import json
from torchvision import transforms
from PIL import Image

# Load metadata
with open('hand_sign_metadata.json', 'r') as f:
    metadata = json.load(f)

# Load model
model = torch.load('hand_sign_model.pt')
model.eval()

# Prepare image
transform = transforms.Compose([
    transforms.Resize((metadata['input_size'], metadata['input_size'])),
    transforms.ToTensor(),
    transforms.Normalize(
        mean=metadata['preprocessing']['normalize_mean'],
        std=metadata['preprocessing']['normalize_std']
    )
])

img = Image.open('hand_sign.jpg').convert('RGB')
img_tensor = transform(img).unsqueeze(0)

# Inference
with torch.no_grad():
    output = model(img_tensor)
    probabilities = torch.softmax(output, dim=1)[0]
    predicted_idx = torch.argmax(probabilities).item()
    confidence = probabilities[predicted_idx].item()

# Get class name
idx_to_class = metadata['classes']
predicted_class = idx_to_class[str(predicted_idx)]

print(f"Predicted: {predicted_class}")
print(f"Confidence: {confidence:.2%}")
```

## Error Handling

The implementation handles:

1. **Invalid ZIP files** → Error: "Invalid ZIP file"
2. **Corrupt/incomplete ZIP** → Error: "Failed to extract ZIP"
3. **Empty class directories** → Error: "Class directory X has no images"
4. **No class directories** → Error: "No valid dataset structure found"
5. **Training failures** → Error message reflected in job status
6. **GPU out of memory** → Falls back to CPU (PyTorch handles gracefully)
7. **Model generation failures** → Job marked as FAILED

All errors are visible on both HOST and USER interfaces via job status updates.
