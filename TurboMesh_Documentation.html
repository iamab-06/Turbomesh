TurboMesh

A high-performance, cross-platform distributed architecture for remote AI/GPU processing over Local Area Networks (LAN).

1. Executive Overview

TurboMesh is designed to solve a specific problem: bridging lightweight user devices (like MacBooks) with heavy-duty processing machines (like Windows GPU desktops) seamlessly over a local network. It offloads complex Machine Learning tasks (like Object Detection and Image Similarity) to the Host, transferring heavy files in optimized, hash-verified chunks, and streaming real-time status updates via WebSockets.

2. System Architecture

[ USER NODE (Mac/PC) ] <======== LAN / Wi-Fi ========> [ HOST NODE (GPU Server) ]

1. Request Pairing -------- (HTTP POST) --------> Generates 6-digit Code
2. Wait for Approval <------- (WebSocket/Poll) ---- User Clicks "Allow" on Host
3. Upload File Chunks ------- (1MB TCP Chunks) ---> Reconstructs & SHA-256 Validates
4. Receive Progress <------- (WebSocket ws://) --- Background GPU Inference Queue
5. Download Results <------- (HTTP GET) ---------> Returns JSON Analytics & Images

3. Component Breakdown

Frontend

User UI (Browser)

Built with lightweight HTML/JS. It handles client-side file chunking via the HTML5 File API and calculates incremental SHA-256 hashes using js-sha256 to prevent massive RAM spikes before data even hits the network.

Backend

FastAPI Core

Both Host and User nodes run on uvicorn and FastAPI. The API is strictly typed using Pydantic models, ensuring robust data validation for cross-platform network payloads.

Security

Auth Manager

LAN environments are inherently untrusted. TurboMesh uses a strict pairing flow: temporary 6-digit codes and physical Host-side approval. Approved devices are issued secure JWT-style access tokens for route protection.

Data

Job & Storage Manager

Ensures 100% data isolation. Every request generates a unique job_id. Files are reconstructed from chunks in a /temporary folder, verified against the client's SHA-256 hash, and moved to /input.

Hardware

Dynamic Device Detection

The Host automatically scans the system using PyTorch to detect the optimal compute backend, gracefully falling back from CUDA (NVIDIA) to MPS (Apple Silicon) to CPU.

ML Pipeline

Asynchronous Workers

ML workloads block the event loop. TurboMesh executes YOLOv8 and ResNet inference in dedicated background threads (asyncio.to_thread), allowing the API to continue serving WebSocket progress updates simultaneously.

4. Artificial Intelligence Capabilities

The Host node comes pre-equipped with two powerful Computer Vision pipelines:

  • Object Detection & Analytics: Utilizes YOLOv8 to detect vehicles and objects. It includes a custom HSV algorithm for vehicle color estimation, a heuristic spatial algorithm for license plate privacy blurring, and outputs comprehensive JSON analytics alongside the annotated image.
  • Deep Image Similarity: Designed for duplicate detection. It combines three algorithms: SSIM (Structural Similarity), pHash (Perceptual Hashing), and deep feature extraction using ResNet-18 embeddings (Cosine Similarity) to output a weighted HIGHLY_SIMILAR, SIMILAR, or DIFFERENT classification.

5. Network & Deployment Rules

Critical LAN Constraints

Because TurboMesh operates over a local network without a centralized cloud relay, the following rules apply:

  • Firewalls: Windows Defender (or macOS Firewalls) will block port 8000 by default. Inbound TCP rules must be added, or the network profile must be set to "Private".
  • Mobile Hotspots: iOS Personal Hotspots strictly enforce Client Isolation (AP Isolation), preventing connected devices from communicating. Standard Wi-Fi routers, Ethernet cables, or unrestricted Android hotspots must be used.
  • 0.0.0.0 Binding: The Host binds to 0.0.0.0 to listen to all network interfaces, but clients must navigate to the specific LAN IP (e.g., 192.168.1.15) or localhost (if testing locally).
